## 一、先说一个好消息：大部分判断根本不需要 AI

这是重算成本后最重要的发现。

话题简述要求「围绕话题连续说至少 7 句」。把这个要求拆开看，**其中大部分是确定性规则，不需要任何模型**：

| 检查项 | 实现方式 | 需要 AI？ | 准确率 |
|---|---|---|---|
| 说够 7 句没有 | ASR 结果按句切分后计数 | **否** | 100% |
| 有没有跑题 | 话题关键词表匹配 + TF-IDF | **否** | 90%+ |
| 有没有用连接词 | 正则匹配 first/second/also/because | **否** | 100% |
| 有没有用超纲词 | 对照课标五级词表比对 | **否** | 100% |
| 漏读没漏读 | 编辑距离（Levenshtein） | **否** | 95%+ |
| 语法有几处错 | LanguageTool / GECToR | 轻量模型 | 80% |
| 逻辑通不通 | LLM | **是** | 主观 |

**结论：7 个维度里只有 1 个真正需要 LLM。** 而且这一项恰好是最主观、最难标定的——既然是免费产品，**它完全可以只给粗反馈（"逻辑一般，建议用连接词"），不给精确分。**

这样一来，AI 成本从"每次模考都要调 LLM"降到"可选增强项"，成本结构完全变了。

### 2.3 GPT4Free (g4f) 的特殊风险

g4f 65,000+ stars，2026 年仍活跃（已改名为 g4f.dev）。但它是**逆向工程第三方网站**获取的免费额度，本质是：

- 上游随时封号 / 改风控
- 无 SLA，随时失效
- **To C 商用有法律风险**（TechCrunch 当年报道其"法律风险自负"）
- 多用户共享同一批账号，容易被上游批量封禁

**结论：g4f 可以做开发期临时验证，绝不能做 To C 生产的依赖。**

### 2.4 额度换算：免费 API 能撑多少人

按每个学生每天 1 次模考、需要 1 次 LLM 调用（话题简述评估）估算：

| 提供方 | 日额度 | 能撑的日活学生 |
|---|---|---|
| OpenRouter | 50 次/天 | **约 50 人** |
| Groq | 1,000 次/天 | **约 1,000 人** |
| Gemini（实际配额浮动） | 数百～数千 | 数百 |

**而 ASR 的消耗更快**：即使口语只有 10 分钟，每次模考约 3–5 分钟需转写音频，1,000 人就是 4,000–5,000 分钟/天——Groq 的 Whisper 免费额度是 2,000 请求/天（按请求数不按分钟），也很快见底。

> **底线结论：免费 API 只够日活几百人的规模验证。超过千人，必须自建推理或付费。**

## 三、To C 免费产品的可行架构

既然免费 API 撑不住规模化，正确做法是**把 AI 调用量压到接近零，重活全放本地**。

### 3.1 三层架构

    第 0 层：确定性规则（零 AI 成本，覆盖 70% 反馈）
      ├ 句数计数、连接词检测、词表比对、要点覆盖率
      └ 纯代码，随产品打包，无服务器成本

    第 1 层：本地语音引擎（自建推理，成本随规模摊薄）
      ├ 完整度 + 准确度  → OpenPronounce（MIT，CPU 可跑）
      ├ 流利度            → torchfa 强制对齐 + VAD
      └ ASR 转写          → Whisper / SenseVoice（CPU 亦可，SenseVoice 169x RTF）

    第 2 层：LLM 增强（可选、可降级、额度有限也无所谓）
      └ 逻辑连贯性建议、语法检查兜底、个性化学习建议
      ├ 主：本地 Ollama + 小模型（Qwen3-4B 等）
      └ 备：Groq / Gemini 免费额度，用完自动降级到本地

### 3.2 关键设计原则

**原则一：AI 降级不是故障，是正常路径**

前端和后端都不要假设 LLM 一定可用。话题简述的反馈分三档：

| 档位 | 触发条件 | 输出 |
|---|---|---|
| 完整 | LLM 可用 | 逻辑评价 + 改进建议 + 分数 |
| 标准 | LLM 不可用 | 要点覆盖率 + 句数 + 连接词统计 + 分数（基于规则） |
| 底线 | 所有 AI 不可用 | 只显示录音回放 + 词表覆盖率提示 |

学生永远能拿到有用的东西。**这比"必须调通 LLM 才能用"的产品体验好得多。**

**原则二：本地推理的成本曲线**

单机 CPU 跑 OpenPronounce + Whisper 大约能支撑几十人同时用。1 万日活的粗算：

| 规模 | 自建方案 | 免费 API 方案 |
|---|---|---|
| 100 DAU | 1 台 4 核机器 | 可行 |
| 1,000 DAU | 2–3 台机器 | **勉强，额度会频繁触顶** |
| 10,000 DAU | 20–30 台机器（≈ 每月几千元云成本） | **不可能** |

关键：**自建的边际成本是线性的、可预算的；免费 API 的成本是不可预测的、会突然归零的。** 对 To C 免费产品，后者是致命的——上游一改政策你就挂。

**原则三：Provider 接口抽象**

把 LLM 和 ASR 都包成统一接口，实现里配置多个后端（A 免费 API / B 本地模型 / C 付费兜底），运行时按可用性自动切换。别把任何一家写死在业务代码里。

## 四、To C 免费产品的真实竞争点

既然免费、既然精度不重要，那护城河在哪？

### 4.1 差异化：反馈颗粒度

商业产品（E听说、驰声）的反馈是**面向考试标准**的：分数 + 错读词列表。对备考够用，但对学习帮助有限。

开源方案能给出**商业产品给不了的东西**：
- 逐音素对照（应该是 /həloʊ/，你读成了 /hɛlnoʊ/）
- 音高/能量曲线叠加显示，一眼看出语调问题
- 停顿位置可视化
- 漏读的具体位置

**OpenPronounce 已经把这些都算出来了**，商业产品不一定展示得这么细。这是免费产品的天然优势——**没有成本约束，可以把每个中间量都画出来**。

### 4.2 差异化：2025 改革后的空白需求

改革取消了中文提示、要求说满 7 句、考察逻辑结构。商业产品的更新周期受制于商业节奏，而**开源方案可以当天跟进政策变化**。

学生现在最需要的反馈是："我说了几句、要点覆盖了吗、逻辑通顺吗"——而这**大部分可以用确定性规则实现**，正是不需要花钱的那部分。

### 4.3 差异化：不怕难听的分数

商业产品要给学校看，分数必须"像模像样"。免费产品可以诚实地说："这个角度你的得分偏低，因为只读了 4 句就停了"——**这种直白的反馈，商业产品因为要维护关系反而不敢给**。

## 五、修正后的结论

| 维度 | 修正前假设（To B） | 修正后（To C 免费） |
|---|---|---|
| 主要成本 | 24 万研发 vs 24 万采购 | **接近 0**（开源 + 规则为主） |
| 精度要求 | 高（需对标正考） | 低（用户明说不在意） |
| 核心约束 | 标定数据、考务关系 | **单次成本≈0 + 稳定性** |
| 成功因素 | 算法精度 | **反馈体验 + 跟进政策速度** |
| 最大风险 | 复刻不了标定数据 | **免费 API 额度撑不起规模化** |

**一句话**：您的判断是对的——**To C 免费场景下，精度不是约束，成本才是**。而复刻的成本比想象的更低，因为大部分判断是确定性规则，AI 只占 1/7 的判断项且可以随时降级。

唯一需要认真对待的是：**别把生产依赖押在免费 API 上**。正确姿势是「规则为主 → 本地模型为基 → 免费 API 做增强 → 付费做兜底」，做成一个 AI 挂了也能用的产品。

# 附录 C · 最终架构：零服务端 · 纯浏览器 · BYOK

> 本附录为最终决策，覆盖前述内容。决策依据来自三轮用户澄清：**核心 To C / 产品免费 / 不提供任何服务 / 全部开销由用户承担 / AGPL-3.0-only 开源**。

## C.1 目标

**我们的开销趋近于零。** 唯一的固定支出是 CDN 和域名。

## C.2 成本归属

| 成本项 | 承担方 | 说明 |
|---|---|---|
| LLM 推理（话题简述评估） | **用户** | BYOK，用户填自己的 key（GLM-4-Flash 永久免费 / 硅基流动 / Groq / Gemini） |
| ASR 转写 | **用户设备** | Whisper via Transformers.js，WebGPU 或 WASM |
| 音素识别 + 评分 | **用户设备** | wav2vec2 ONNX via Transformers.js |
| G2P（文本→音素） | **用户设备** | espeak-ng WASM |
| 规则层 | **用户设备** | 纯 TypeScript，零推理 |
| 音频存储 | **无人** | 不出浏览器，处理完即丢 |
| CDN + 域名 | **我们** | 唯一的真实支出 |

## C.3 组件清单（全部浏览器端）

| 层 | 组件 | 许可 | 形态 |
|---|---|---|---|
| 推理引擎 | Transformers.js + ONNX Runtime Web | Apache-2.0 / MIT | npm |
| 加速 | WebGPU（有则用，无则 WASM 回退） | W3C 标准 | — |
| 音素模型 | onnx-community/wav2vec2-lv-60-espeak-cv-ft-ONNX | Apache-2.0 | HF Hub，按需下载后缓存 |
| G2P | espeak-phonemizer 0.1.2 | GPL-3.0-only | npm，WASM |
| ASR | onnx-community/whisper-base（tiny/base 可选） | MIT | HF Hub |
| 规则层 | 自研 | AGPL-3.0-only | 本仓库 |

## C.4 为什么 AGPL-3.0-only 是助力而非负担

1. **许可障碍消失**：espeak-ng（GPL-3.0）与 espeak-phonemizer（GPL-3.0-only）可直接使用，唯一的义务是开源——而项目本来就是开源的。
2. **未来无锁定**：AGPL 明确覆盖网络交互场景。以后若需要加自建后端或接付费 API，许可证不构成任何限制。
3. **依赖可传染也可接受**：任何 GPL 组件并入都不产生额外义务。

## C.5 三个已知风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| **首次下载量**（音素模型 + Whisper 合计 150–300MB） | 一半用户可能直接流失 | 首屏明示下载体积；模型延迟加载；先让用户做不需要模型的环节（听力题、录音、回放） |
| **WebGPU 覆盖不足**（Safari 弱、Firefox 待完善） | 性能下降 | 强制 WASM CPU 回退路径；检测并提示用户 |
| **低端设备算力不足** | 达不到实时 | 首次使用时做一次基准测试，不达标则引导降级到「规则层优先」模式 |

## C.6 零成本护城河（服务为零时，资产是什么）

1. **反馈颗粒度** —— 逐音素对照、音高曲线、停顿位置。商业产品需维护学校关系，不敢给这种直白反馈。
2. **政策跟进速度** —— 2025 年取消中文提示这类变化，开源方案当天可改；商业产品受制于排期。
3. **无门槛进入** —— 无需账号、无需登录、无需家长付费、无需学校采购审批，打开即用。

## C.7 开发路线（零成本分层）

| 层 | 依赖 | 状态 | 说明 |
|---|---|---|---|
| **L0 规则层** | 无（纯 TS） | **立即可做** | 句数、连接词、超纲词、漏读、要点覆盖、流利度指标。零模型零 API。 |
| **L1 音素层** | Transformers.js + ONNX | 需下载模型 | 音素级比对、发音错误定位 |
| **L2 ASR 层** | Whisper ONNX | 需下载模型 | 话题简述转写 |
| **L3 LLM 层** | 用户 key | 用户自备 | 语法建议、逻辑评价（可降级） |

**L0 不依赖任何模型或 API，因此可以独立完成、独立验证、独立发布。** 这是最小可运行切片。
