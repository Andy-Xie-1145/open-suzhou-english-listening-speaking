# 开源复刻中考英语听说考试评分引擎 · 可行性研究

> 调研日期：2026-08　|　对标标的：苏州市九年级中考听力口语自动化考试（30 分）
> 结论提要：**朗读与情景问答两类题的技术复刻可行性高；话题简述（开放题）是难点但也正是提分点。核心算法组件全部有 MIT/Apache 开源实现，缺的是中文母语青少年的开放表达标注数据。**

---

## 0. 一句话结论

商业定价给了我们一个非常明确的信号：

| 形态 | 价格 | 供应商 |
|---|---|---|
| 校级系统采购 | **240,000 元/套** | 驰声教考练平台 V5.0 |
| 校级系统采购 | **345,000 元/套** | 外研在线 U听说自适应学习与训练系统 |
| C 端年费 | **308 – 460 元/年/账号** | 讯飞 E听说中学 |

这个价格里，**算法不是主要成本**——主要成本是「15 年积累的评分标定数据 + 几万所学校的考务关系 + 教研服务团队」。算法部分本身已有成熟开源实现。

**可行性判断：中高可行，但商业逻辑需要重新定义**（详见第 6 节）。

## 1. 最关键的发现：评分维度的现成对标

### 1.1 speechocean762 —— 人群几乎完全吻合

| 属性 | speechocean762 | 苏州中考目标人群 |
|---|---|---|
| 规模 | 5000 条英文话语 | — |
| 说话人 | 250 人 | 苏州市全体初三生 |
| 母语 | **全部为普通话母语者** | **全部为汉语母语者** |
| 年龄 | **125 成人(≥18) + 125 儿童(<18)** | 约 13–15 岁 |
| 语言 | 英语（非母语） | 英语（非母语） |
| 标注 | 5 位专家独立标注，句/词/音素三级 | 人工评定的口语分 |

**这是目前公开数据集中与苏州中考考生画像最接近的一个。** 母语一致、年龄覆盖儿童段、L2 英语、专家打分——四个条件同时满足。

### 1.2 标注维度与考试评分维度一一对应

speechocean762 的原始字段：

    accuracy      -> 准确度
    completeness  -> 完整度
    fluency       -> 流利度
    prosodic      -> 韵律 / 语调
    total         -> 总分
    words[]       -> 词级（phones / phones-accuracy / stress / mispronunciations）

对照考试公布的三个口语评分维度（准确度 / 流畅度 / 完整度）+ 2025 年新增的语调考察，**speechocean762 的标注 schema 可以直接作为我们评分模型的训练与验证基准**。

获取方式：
- OpenSLR SLR101：speechocean762.tar.gz **520 MB**，许可 **CC BY 4.0**
- HuggingFace：mispeech/speechocean762（test split 2500 条，load_dataset 直接加载）

### 1.3 OpenPronounce 的评分公式与「完整度占七成」惊人吻合

Halleck45/OpenPronounce（MIT）的总分公式：

    score = 0.3 * acoustic
          + 0.4 * (1 - phoneme_error_rate)
          + 0.3 * (1 - word_error_rate)

每项截断到 [0, 100]；权重与阈值在 500 条专家评分的 speechocean762 语音上拟合，与人类总分的 **Spearman 相关系数 rho = 0.65**（某一子维度达 0.83）。

**注意其中的巧合**：(1 − 音素错误率) 权重 0.4，(1 − 词错误率) 权重 0.3——两者都是「有没有把该说的说出来」的度量，合计 **0.7**，恰好对应教辅口径的「完整度占了七成」。

这不是巧合——**这很可能就是国内主流厂商评分公式的同源思路**：完整度用「音素级不完整 0.4 + 词级不完整 0.3」来刻画，剩下的 0.3 给声学质量（发音清晰度）。

> 口径提示：Spearman rho = 0.65 意味着与人类专家评分的相关性中等，属于可用但需谨慎的水平。讯飞/驰声未公开相关系数，无法直接对比。

## 2. 组件清单：五个评分维度逐个拆解

### 2.1 完整度（权重最高，约 70%）—— 可行性 5/5

**这是最有商业价值的一环，因为教辅明确说「只要完整说出来就有 70% 分」。**

| 组件 | 用途 | 许可 | 备注 |
|---|---|---|---|
| **OpenPronounce** | 音素级 + 词级双模型，DTW 对齐，输出漏读/多读/错读 | MIT | pip install openpronounce，CPU 可跑 |
| facebook/wav2vec2-lv-60-espeak-cv-ft | 识别「实际发出」的音素（不经语言模型纠正） | Apache-2.0 | OpenPronounce 底层用 |
| slplab/wav2vec2-large-robust-L2-english-phoneme-recognition | 专为 L2 英语音素识别微调 | 开源 | 备选/微调起点 |
| espeak-ng | 文本 G2P，生成「标准音素」 | GPL-3.0 | 系统依赖，注意许可 |
| g2p-en-plus (PyPI) | 英语 G2P 纯 Python 替代 | 开源 | 可避开 espeak 的 GPL 依赖 |
| CMU Pronouncing Dictionary | ARPAbet 发音词典，10 万+ 词 | 自由 | 配合 kyubyong/g2p |
| 编辑距离 / WER | 词级完整度计算 | — | 自行实现，几十行 |

**实现路径**：参考文本经 G2P 得到标准音素序列；音频经 Wav2Vec2 得到实际音素序列；DTW 对齐后逐音素比对，检出**替换 S / 删除 D（即漏读）/ 插入 I（即多读）**；PER 与 WER 直接进公式。

### 2.2 准确度 / 发音错误 —— 可行性 4/5

| 组件 | 说明 |
|---|---|
| **OpenPronounce** | 直接输出每个错读词的 expected → actual IPA 与置信度，例：hello: expected /həloʊ/, heard /hɛlnoʊ/ (confidence 89%) |
| 音素混淆对约束 | 参考 ISCA 2024「Enhancing GOP in CTC-Based Mispronunciation Detection with Phonological Knowledge」：用发音学约束限制替换只发生在**发音相近的音素对**之间，可显著降低误报 |
| GOP（Goodness of Pronunciation） | 经典方法（Kaldi 系），wav2vec2 时代被端到端 CTC 方案取代，可作对照基线 |
| SpeechBlender | 合成式发音错误数据增强，论文报告 PCC +5.05%、F1 +4.64% |
| Echoic | 新开源音素级实时评分工具，可参考其交互设计 |
| superasymmetry/pronounce-assess | 实时发音准确度评估 Python 库 |

### 2.3 流利度 —— 可行性 4/5

| 组件 | 用途 |
|---|---|
| **torchfa** (PyPI) | 基于 torchaudio MMS 模型的强制对齐，输出每个词的精确时间戳——**这是算语速和停顿的基础** |
| torchaudio.functional.forced_align | 官方 API，CPU/CUDA 实现 |
| MMS_FA / mms-300m-1130-forced-aligner | 多语种强制对齐，1100+ 语言 23000 小时训练 |
| Whisper filler 检测 | 填充词（um/uh/er）检测，文献显示 Whisper 在填充词上优于 Coqui STT |
| 能量 / VAD 分析 | 静音段检测、语流中断计数（librosa 或 silero-vad） |

**流利度指标可直接构造**：有效语速（音节/秒）、静音段数量与总时长、填充词密度、单句最长停顿、语速方差（忽快忽慢扣分）。

> 这一点与考试要求高度对应——教辅明确提醒「不能语速过快，尽量保持语速均匀，不要忽快忽慢」，说明**语速方差是真实评分项**，可以量化。

### 2.4 韵律 / 语调 —— 可行性 3/5

| 组件 | 说明 |
|---|---|
| OpenPronounce | **已直接输出 pitch 与 energy 曲线**，无需额外集成 |
| 音节级重音定位 | speechocean762 的 stress 字段提供标注，可训练重音检测头 |
| praat-parselmouth | Praat 的 Python 绑定，做 F0 轮廓、重音、intonation 分析 |

此项最难，因为「语调自然度」高度依赖主观标准。但对**朗读题**（有标准文本）可用「与参考音频的 F0 轮廓相关性」做代理指标；对**开放题**则需要人工标定数据。

### 2.5 语法正确性 + 逻辑结构（2025 新增维度）—— 可行性 3/5

这是 2025 年改革新增的考察点，也是**唯一没有现成开源方案**的部分。

| 子维度 | 方案 | 组件 |
|---|---|---|
| 语法 | 序列标注式 GEC | **GECToR**（Grammarly 提出的架构）、LanguageTool（Java，开源）、LLM 直接判定 |
| 信息完整性 | 关键词覆盖率 + 要点匹配 | 话题关键词表 + TF-IDF / 语义相似度 |
| 逻辑结构 | 连贯性分析 + 评分 | discourse connective 计数（first/second/also/because…）、LLM 评判 |
| 句数门槛 | 计数 | ASR 结果按句切分，**检查是否 ≥7 句**（硬性要求，可 100% 精确判定） |

> GEC-Info（gotutiyan/GEC-Info）是收集 GEC 开源实现的索引仓库，适合作为选型入口。

### 2.6 听力部分 —— 无 AI 需求

「听对话回答问题」「听对话和短文答题」是客观题，考的是音频播放与答题卡，**不需要任何 AI**。这部分的工作量是题库与播放器，不是算法。

## 4. 五道题型的可行性逐题评估

| 题型 | 归属 | 技术难度 | 核心依赖 | 结论 |
|---|---|---|---|---|
| 听对话回答问题 | 听力 | **无 AI** | 音频播放器 | 100% 可复刻 |
| 听对话和短文答题 | 听力 | **无 AI** | 音频播放器 | 100% 可复刻 |
| **朗读短文** | 口语 1 | **中** | OpenPronounce + G2P | **90% 可复刻**，且能给逐音素反馈，比多数商业产品更细 |
| **情景问答** | 口语 2 | **中** | ASR + 文本对齐 + GEC | **85% 可复刻** |
| **话题简述** | 口语 3 | **高** | ASR + GEC + LLM + 逻辑分析 | **60–70% 可复刻**，是差异化的胜负手 |

**重要认知**：题目 3、4、5 的**参考文本都是已知的或半已知的**——朗读有原文，情景问答有预设情境，话题简述只有话题名但有要点清单。这意味着**大部分判定可以做「有监督的文本对齐」而非「开放式主观评判」**，这大幅降低了难度。

### 4.1 话题简述的具体设计建议

考试只给话题（如 My favourite sport），要求**围绕话题连续说至少 7 句**。这意味着我们可以构建：

    话题 → 要点清单（评分点）→ 必说要素（可判定）→ 加分要素（可加分）

**可判定的硬指标（无需 LLM，100% 可靠）：**
- 句数 ≥ 7（切句后计数）
- 关键信息是否出现（时间/地点/人物/事件/感受）
- 是否使用连接词（first / second / also / because / however）
- 是否包含真实个人信息（考试明确要求避免，此项应为**扣分**信号）
- 超纲词比例（对照课标五级词汇表——教辅明确建议「避免使用超纲词」）

**需要模型判断的软指标：**
- 语法正确率（GECToR / LLM）
- 逻辑连贯性（LLM 打分）
- 语句丰富度（同义替换、句型多样性）

**这个设计的产品价值极高**：学生最需要的正是「我说了几句、要点覆盖了吗、逻辑通顺吗」的即时反馈——而这恰恰是 2025 年改革后被市场验证的需求。

### 5.1 与采购方案对比

| 项目 | 采购商业系统 | 开源复刻 |
|---|---|---|
| 一次性成本 | 24 – 34.5 万元/套 | 0（全部 MIT/Apache/CC-BY） |
| 许可限制 | 采购合同限制（通常限校/限年） | 无，可商用（注意 espeak-ng 为 GPL，建议隔离或换 g2p-en-plus） |

### 5.3 成本对比结论

即使按 8 人月、人均月成本 3 万元计算，**一次性研发投入约 24 万元**，与采购一套 24 万元的系统相当，但：
- 无年度续费、无授权限制、数据自持
- 可用于多地区、多教材（不止苏州）
- 可持续训练自有模型，形成真正护城河

**但商业逻辑要重新想清楚**：如果目标只是「苏州中考这一个市场」，24 万买套系统更划算。开源复刻的价值在于**做成产品卖向全国**（江苏 13 地市，以及译林版教材覆盖的其他省份），或者**作为自有产品的技术底座**。

## 6. 真正的风险（比技术难度更重要）

### 6.1 风险一：无法对齐正考评分（不可解）

讯飞的正考评分引擎不对外，我们**永远无法保证「我们的分 = 正考的 30 分」**。

**应对**：不要以「模拟正考得分」定位，而以「能力诊断与提分」定位。明确告知用户「这不是考场分数，这是告诉你离满分别差什么」。可以用正考真题做外部校准，观察分数相关性，但不承诺一致。

### 6.2 风险二：开放题无标注数据（可缓解）

speechocean762 是**朗读**语料（read-aloud），而话题简述是**自发表达**。公开数据集里没有「中国初中生围绕指定话题自由说 7 句」的标注。

**应对**：自建。只需标注 3000 – 5000 条话题简述录音即可启动（按 3 人 × 2 周估算）。录音可由学生自愿采集，标注是主要成本。

### 6.3 风险三：商业产品的护城河不是算法（认知陷阱）

驰声自己说「**沉淀 5600 万小时口语数据**」「稳定运行 **15 年零事故**」。这不是靠某个开源库实现的，靠的是：
- 十几年的真实考试录音沉淀
- 与命题专家反复标定的评分阈值
- 全国考务体系的关系

**开源能复刻算法，复刻不了标定数据和行业关系。** 但——对于**教学/练习市场**，标定精度要求远低于高利害考试，教学容错率高得多。这正是机会窗口。

### 6.4 风险四：音素级 PER 在中国青少年语音上的可靠性（需验证）

speechocean762 有 125 名儿童说话人，可以**直接用来验证**模型在目标人群上的表现。

**建议的最小验证实验（2 周可完成）：**
1. 拉取 speechocean762 test split（2500 条，HF 直接加载）
2. 跑 OpenPronounce，与人工标注的 accuracy/completeness/total 算 Spearman 相关
3. 分别统计成人组与儿童组的相关性差异
4. **若儿童组相关性显著低于成人组，则必须用儿童数据微调**——这是 go/no-go 的第一个决策点

> 这是我建议**最先做的事**：一个下午的工程量，就能决定整个方向是否值得投。

## 7. 执行路线建议

### 第 0 阶段（1 周）：可行性验证 —— 先做这个
- 用 speechocean762 跑通 OpenPronounce，计算与专家评分的相关性（分成人/儿童组）
- 结论：相关性达标 → 继续；儿童组显著偏低 → 转微调路线
- **成本：几乎为零（开源 + 免费数据）**

### 第 1 阶段（1 – 2 个月）：朗读题 MVP
- 集成 OpenPronounce，接入考场流程的录音环节
- 实现音素级反馈 UI（逐词标红 + expected/actual IPA）
- 用 speechocean762 标定权重，替换 OpenPronounce 默认权重
- **交付物**：能替代「E听说朗读部分」的网页/小程序

### 第 2 阶段（2 – 3 个月）：情景问答 + 话题简述
- 接入 ASR，建立 12 个（或更多）话题的要点库
- 接入 GEC（先试 LanguageTool + LLM），做语法正确率
- 实现句数、连接词、要点覆盖、超纲词的硬性判定
- **同步启动标注**：自采 3000 条话题简述录音

### 第 3 阶段：信创与规模化
