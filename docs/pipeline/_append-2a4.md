### 2a-4. 含正则／反斜杠／转义序列的文件，**禁止用模板字符串或 here-string 拼接写**（第 192 轮补）

**规则：**

任何包含正则表达式、反斜杠或转义序列的文件（`\s` `\d` `\.` `\n` `\\` 等），
**一律用 `tools.write` 直接写完整内容，或在 JS 里用 `String.raw`。**

**禁止：**

- JS 普通模板字符串（反引号）拼接——**它会把 `\s` 静默吃成 `s`，把 `\.` 吃成 `.`**
- PowerShell here-string `@"..."@` / `@'...'@`——**本项目已因此损坏过多个文件**

**为什么这条必须硬：**这类损坏**产出的文件看起来完全正常**——
字节数对、末尾换行在、UTF-8 合法、**没有任何编码检查会报**。
它只在**跑起来、正则失配**的那一刻才暴露，而那时的现象是「结果不对」，不是「文件坏了」，
**排查方向会完全跑偏。**

**实例（第 192 轮真实事故）：**`docs/pipeline/sentence-gate.ps1` 的阈值正则
`不少于\s*(\d+)\s*句` 被写成 `不少于s*(d+)s*句`，一跑即 exit 2。
更糟的是它恰好卡在基线 commit `a7dc360` 落盘与修好之间，
**基线里收录的就是那份坏文件，任何人 checkout 拿到的都是坏的。**
**同一个晚上还有：`scripts/facts.ps1` 的 `\s` 被吃成 `s`，导致题块统计全为 0。**

**配套硬动作：写完含正则的文件必须实跑一次，验证行为正确。**
**「文件写出来了」不等于「文件是对的」**——这两件事之间隔着一个必须执行的动作。

**这条与 §2a-3 同族：都在说「你以为你写下的东西和你实际写下的东西不是一回事」。**
区别是 §2a-3 出在**字符串内容**上，本条出在**字符串的转义过程**里——**更隐蔽，因为它连内容都不是你写的那个。**
