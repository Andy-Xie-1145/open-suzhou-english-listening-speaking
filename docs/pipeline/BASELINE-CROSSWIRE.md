# 基线串线排查（BASELINE-CROSSWIRE）

> 第 114 轮建立。起因：`R1-B6.md` 的前置校验三栏**取自 `A12.md`**（MD5／字节数／行数三项与 A12 逐项吻合）。

## 一、为什么这比「没有基线」更危险

| 态 | 表现 | 对 `check-integrity` 的后果 |
|---|---|---|
| **串线** | 报告记了一个**看起来完全正常**、实则属于别的文件的基线 | **主动给出错误答案**——MATCH/MISMATCH 判定不可信 |
| **缺基线** | 报告根本没记 MD5/字节/行数 | 判 UNVERIFIED，**不会给出错误答案** |
| **过期** | 记的是本批真实前像，但文件此后已被修复 | 判 MISMATCH，**这是正常且可解释的** |

**三者里只有第一种会骗人。**「看起来齐全」正是它危险的地方。

## 二、判据（只报这一种，不报「未吻合」）

> **某 MD5 能在另一个批次的文件上逐项吻合（MD5 + 字节数 + 行数 三项全中）。**

**未吻合是正常的**——文件在 R1 之后被修复，MD5 当然对不上当前值。**只有吻合到别的批次才是问题。**

**没有 MD5 的要单独列**：那是缺基线，处置不同，不能和串线混为一谈。

## 三、执行时必须踩准的四点（每一条都对应一次真实漏检）

1. **从报告正文 grep，不要凭记忆。**本轮已有五人栽过：reviewer-1 两次、reviewer-2 两次、writer-bcd 一次。**每次都是 MD5 或尾行断言救下来的。**
2. **一份 R1 可能记多条基线**（审核时的、并发改动后的、补记的……）。**全部抽出逐个比对——只比最后一条会漏。**
   本轮实测有多条基线声明的批次：A19(4) A20(5) A32(2) A8(2) B4(2) C5(3) E3(2)。
3. **只认基线语境里的 MD5。**有的报告正文里有几十个 MD5（跨批查重表、索引清单），**那些不是基线声明**。
   判法：取该 MD5 所在行的**上下各 4 行**窗口，窗口内须出现「前置校验／字节级／基线／字节数／行数」之一。
4. **批次名有别名。**`R1-A0→A-batch0`、`R1-B1→B-batch1`、`R1-C1→C-batch1`、`R1-D1→D-batch1`、`R1-E1→E-batch1`、`R1-A6-true→A6`。

**串线：1 处（全库唯一）**

### 范围扩大过一次，是被「返回条数不可信」逼出来的

1. 第一遍**只查了 58 份 `R1-*`**，结论「全库只有 B6」。
2. 第二遍改查 `reviews/` **全目录 → 实际 220 份**，含 `CL-*` 销案记录、`RECHECK-G*`、`WEAK-REFUTATION-SCAN` 等。
   **多出的 162 份里没有第二处串线——但必须查过才能这么说。**

### 三份「多批次报告」，解析时不能按单批处理

| 报告 | 覆盖批次 | 核验 |
|---|---|---|
| `RECHECK-G1.md` | A1 / A2 / A5 | 其 `9ed274f7…`＝**A2.md**、`1c447628…`＝**A5.md**，与声明范围一致 |
| `RECHECK-G2.md` | 跨多类多批 | 同上 |
| `RECHECK-G3.md` | A-batch0 / A3 / A4 / E-batch1 | 其 `4aa8b4e6…`＝**A4.md**，与声明范围一致 |

**若按「文件名＝批次」解析这三份，会把它们正确的引用全判成串线——本轮实测一度产生 18 条误报。**

**处置：报告若覆盖多批，MD5 归属按它自己声明的批次范围判，不按文件名判。**

## 五、查出串线后的处置（按判据执行，不得自行改题目文件）

| 该批次后来有没有修复记录？ | 处置 |
|---|---|
| **有** | 用**修复记录的自测基线**作替代锚；**必须在报告里注明「R1 基线不可采信，锚点为 F 记录的自测值」** |
| **没有** | 闭合证明**无解**，判 **UNPROVEN** 并如实标注 |

**B6 属第一类**：`F1-B6.md` 完好，其自测基线 `9d5ea61a436a99aea1452c1642d29617`（10054 字节 / 213 行 / 2026-10-04 06:56:36）已补记进该文件。

**锚点强度的注意事项**：`check-integrity.ps1` 会把 `reviews/` 与 `fixes/` 路径上的锚点**降级为弱**，`$strong` 优先。
所以**替代锚要写在 `reviews/` 下**才有强锚效力——B6 的强锚由 `reviews/R2-B6.md` 承担（批次名与 MD5 同行）。

## 六、本文档的复查方法

1. 枚举 `data/item-bank/` 下全部 `.md`（排除 `reviews/`、`fixes/`），逐个算 MD5 / 字节数 / 行数，建索引；
2. 枚举 `reviews/R1-*.md`，**逐批**取权威份（同批次多份取最高后缀）
3. 按「四、判据」逐批比对；**多基线声明的批次逐条比**；

4. 未吻合**不报**，只把缺基线的单独列出。
