## 10. 与任务书描述不符之处（_COMMON §7 要求明确写出）

1. **「共 27 个批次」——成立，但构成在审计期间发生变化。**
   任务书写「根目录下全部批次 + prod 下未归档批次，共 27」。审计开始时为根目录 23 + prod 4；
   审计期间 **D6 从 prod/ 归档到根目录**，最终为根目录 24 + prod 3。总数 27 不变，结论不受影响
   （D6 的 MD5 归档前后同为 `317B44D1…`，是移动不是改动）。

2. **「Jaccard 相似度…阈值 0.6」——该阈值在本库无区分力，照此执行会漏掉全部真实撞题。**
   实测 38,062 对中 0 命中，最高 0.308（距阈值差近一倍）。
   而第 4 节确认的 3 处撞题，Jaccard 实测分别为 **0.077 / 0.000 / NaN**。
   **即：任务书规定的相似度方法无法发现本报告报出的任何一处真实撞题。**
   撞题全部是通过「标题提取 + 两两比对」这条路径发现的，不是通过 Jaccard。建议后续调度改用标题比对为主、相似度为辅。

3. **Jaccard 对 E 类结构性失效，任务书未给替代度量。**
   E 类 40 份材料（4 个批次）的情景提示与考点说明为中文，英文 token 集为空，
   **E↔E 与 E↔A/B 的 Jaccard 全部返回 NaN 或 0**。任务书只说「分开查」，未规定怎么查。
   本审计改用 CJK 字符 Jaccard 补测：600 个 E 类跨批次对，≥0.6 命中 0，最高 0.388
   （E-batch1 E-04《同学生日会》 × E2 E2-01《校园开放日》）。
   **M2（E3-05 × E4-10，标题逐字相同）正落在这一盲区里。**

4. **任务书举的三个示例值，实测均不构成「反复出现」。**
   任务书写「同一组数字（**45 元、7:30、Room 302** 这类具体值反复出现）」。实测反证：

5. **「E 类材料是中文情景提示，与其他类别的比对方式不同，分开查」——成立，已照做**（见 8.4、9.2、5.4）。

6. **「`C3.meta.md` 是旁挂文件，排除」「REVIEW-RUBRIC.md 与 INDEX.md 排除」——均成立，已照做。**
