# 任务 R2-A27：A27 第二轮独立审核

## 输入

- 被审文件：`data/item-bank/prod/A27.md`（若已归档到 `data/item-bank/A27.md`，以归档版为准并在报告写明）
- **第一轮报告（授权你读这一份）**：`data/item-bank/reviews/R1-A27.md`
- **修复记录（授权你读这一份）**：`data/item-bank/fixes/F1-A27.md`
- 审核规范：`data/item-bank/REVIEW-RUBRIC.md`（**全文**，定级一律引它的条目号）
- 通用规约：`docs/pipeline/dispatch/_COMMON.md`（**全文**）

## 本轮要回答两个问题

### 一、第一轮报的每一条缺陷，现在真的修好了吗

逐条打开第一轮报告的缺陷清单，回到**当前磁盘上的题目原文**逐字核验。
**不采信修复记录的自述结论。**修复记录写「已修」不算，要自己看。
**对每一条给出：已修 / 未修 / 改出新问题。**

### 二、修复有没有改出新问题

这是本轮的重点。**修复动作本身可能制造缺陷**，今日已有实例：
- 处方只改材料数字、不管引用该数字的选项 → 照抄后正确选项失去材料支撑，好题变错题
- 改答案字母后触发 1.8 违规（连跑、字母缺用）
- 重排选项行序时误改干扰项文本 → 制造新的无材料支撑排除依据
**逐条检查修复记录的授权改动之外，是否有未授权的改动。**
用反向替换回原值后重算 MD5，比对基线——**这与修复员用的是同一手法，你要独立做一遍。**

## 必查项

1. **字节级前置校验**：`ReadAllBytes` 算 MD5 与字节数，行读取复读比对，两次一致才继续。
   **并与第一轮报告记录的基线 MD5 对照**——不一致说明修复确实动过，这是预期内的；
   但你要确认改动范围与修复记录的授权一致。
2. **逐题逐选项判定（15 题，不许抽样）**：把 Answer 字母所指选项拿回材料找逐字依据。
   **末尾汇总行与 Answer 行逐位一致，只证明两处抄的是同一份答案，证不了那份答案是对的**——
   A21、A27、A29、A30、A32 五批都栽在这上面。逐题独立核，不要只比汇总行。
3. **答案排列**：周期 p=1..⌊n/2⌋、最长连跑 ≤2、四字母齐备、末尾汇总行逐位一致。
4. **语义查重**：`python scripts/topic-guard.py check`，候选行写成「题号<TAB>标题+材料+题干」。
   **命中超阈值项逐条判读是不是同一考点**，脚本只报相似度。
5. **说话人闸门**：`pwsh -NoProfile -File docs/pipeline/speaker-gate.ps1 data/item-bank/prod/A27.md`，退出码须为 0。
6. **词数、结构比、编号连续性、末尾换行**。

## 角色隔离

- **只许读上面点名的第一轮报告与修复记录**。其他 `reviews/` 与 `fixes/` 下一律禁读。
- `grep` 必须显式限定 path，绝不对 `data/item-bank` 整目录 grep。
- **不得修改被审文件。**
- 定级必须引 REVIEW-RUBRIC 条目号，**不要自行加严**（历史上出过三次审核员加严的事故）。

写入 `data/item-bank/reviews/A27-r2.md`。

- **必须有「第一轮缺陷逐条核验表」**——每条缺陷一行，列出第一轮定级、修复记录的做法、你的核验结果（已修/未修/改坏）、你的定级。
