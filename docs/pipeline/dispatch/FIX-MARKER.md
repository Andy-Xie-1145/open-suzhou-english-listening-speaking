以下 8 份材料的**结构标记与实际体裁不符**：它们是对话（材料正文以 `M:` / `W:` / `Boy:` / `Girl:` 等说话人标注起句），

> 逐段读材料正文，判断它到底是对话还是叙述，再决定改或不改。
> **若某段实际是叙述（正文没有说话人标注），就不要改它，并在记录里写明。**
> 若某段还有扫描漏掉的，同样处理。

## 为什么这是缺陷

同一批 D 类里，体裁相同的材料必须标同一种标记。D5 与 D6 都已统一，
D-batch1 与 D4 因为混用而被审核判为中等缺陷（D6 的同类问题见 R1-D6 的 M-1）。
**这两个批次的同类缺陷此前一直没被发现**——直到第 46 轮调度方用脚本做全库结构扫描才暴露出来。

## 硬性边界

1. **只许改结构标记那一行**，即 `**Passage**` 改成 `**Dialogue**`。
2. **材料正文、表格、Word Bank、Answers 行、末尾汇总行，一个字节都不许动。**
3. 改完跑 `wordcount-gate.ps1` 与 `verify-bank.ps1`，贴原始输出。
   **注意**：这两个脚本靠结构标记定位材料正文，所以改完必须确认词数统计仍然正常。
4. **自证**：把改过的标记逐字改回后，两个文件的 MD5 都应精确回到改前的值。

## 输出

写入 data/item-bank/fixes/FIX-MARKER.md，包含：
- 改前两个文件的 MD5 与字节数
- 逐段列出：实际体裁判定（对话/叙述）、扫描是否报此项、改或不改、改前改后文本
- 材料正文与 Answers 行零改动的自证
- 改后两个文件的 MD5 与字节数，以及反向套用复现基线的结果
- 两个闸门的原始输出
- 若发现扫描漏报或误报，写明
