## 0.1 对既有文件的写入：先确认读到的是全文

> **本条来自第 113 轮的真实事故**：同一执行者在两小时内两次用 `tools.read` 带 `limit` / `offset` 只读部分，
> 却把这份**片段**当**整份**写回，**先后截断了自己的脚本文件头与五份修复记录**。

**规则**：

1. **凡是对既有文件的写入，必须先确认读到的是全文。**
2. **若只读了部分，禁止把该结果当整份写回。** `limit` / `offset` 返回的是**片段**。
3. **要改就在已读全文的前提下改；要追加就用追加模式，不要整份覆盖。**
4. **写回前核对两个数**：写回后的字节数应与预期一致；**若写入后文件明显变短，**立即停止并恢复**，不要先继续做后面的事。
5. **新建文件不受此限**——本条只针对**修改既有文件**。

### 0.1.3 写入禁令：**含 Markdown 反引号的文本，禁止用 PowerShell 双引号 here-string 写入**（第 194 轮补）

> **本条与 §0.1 属同一族事故（写入通道选错导致文件被写坏），但坑不同，故分开写、不合并成一句。**
> §0.1 管的是「拿片段当全文」；**本条管的是「写入通道会吃掉字符」。**
> 与 §2a-4（禁止用模板字符串／here-string 写含正则的文件）同族、可互相引用，**但坑不一样**：
> §2a-4 的坑是**正则与 `$` 被解释**，本条的坑是**反引号被解释**。

**规则**：

1. **反引号是 PowerShell 的转义符，不是普通字符。** 双引号 here-string（`@"…"@`）与双引号字符串中：
   `` `r `` → **CR（0x0D）**、`` `n `` → LF、`` `t `` → 制表符。
2. **第 194 轮实测后果**：写入形如 `` `reviews/CL-E3.md` `` 的路径时，**`reviews` 变成 CR + `eviews`**，**静默**落盘。
   **8 个文件同时被污染，而写后自查三项（CRLF=0／FFFD=0／末尾 0x0A）全部通过**——由 `encoding-check.ps1` 抓出。
3. **写入一律用 `tools.write`，或 `[System.IO.File]::WriteAllText($p, $text, (New-Object System.Text.UTF8Encoding($false)))`。**
4. **若必须用 PowerShell 生成待写文本**：改用**单引号 here-string**（`@'…'@`，不插值、不解转义），或先剔除内容中的反引号。
5. **写后必查裸 CR**（§2d.1 第 4 项）。**含反引号的写入，这一项不是可选项。**

### 0.1.2 移动与删除（reviewer-4 两次操作事故后补）

**事故一：搬运没生效，却先删了源，内容一度丢失。**
错在顺序——**先删源、后验目标**。

**事故二：报告「空目录已删除」，实际路径里的反斜杠被当转义符吃掉**，
命令作用在一个不存在的路径上，`Test-Path` 返回 False，于是「以为删成了」。

**两次是同一个毛病：把「命令没报错」当成「事情做成了」。**

**规则**：

1. **删除任何东西之前，必须先确认目标已存在且内容正确。**「先删源」永远是错的顺序。
   **正确顺序：写目标 → 校验目标完整 → 再删源。**
2. **`Test-Path` 返回 False 有两种含义**：路径不存在（你要的），或**你拼错了路径**（危险）。
   **删除前必须四项确认：存在 / 是空 / 不等于正规目录 / 叶名相符。**
   **（这四项原写成「三重」是笔误，已订正——照做的人会漏掉一项。）**
> ### ⚠️ 但上面三条都治的是症状 —— 真正的机制在下面（第 114 轮补，reviewer-4 的第二次事故）
> 
> **Windows 路径里的反斜杠，经工具调用传给 PowerShell 时被当成转义符**：
> `\P`、`\r`、`\e` 各被吃掉一截，实际作用在一个**从未存在过**的路径上。
> 
> **证据就在它自己打印的输出里**：
> ```
> D:ProjectsOpen English Listening and Speakingeviews
> ```
> 反斜杠没了，`\r` 还把行拆开了。**当时多看一眼这行，假成功当场就暴露**——
> **但它是先信了 `Test-Path` 的返回值，才回头去查目录还在不在。**
> 
> **同会话内同型踩坑共四次**：
> - JS 模板串里的 `\s` 被吞成 `s`，分词正则失效、报出错误词数（并误判一个分句为不可解析）
> - PowerShell 里 `$L` 覆盖 `$l`（**变量名不区分大小写**）
> - `$expected_$b` 插值歧义
> - 上述反斜杠被吃
> 
> **共同根因：控制字符在字符串传递中被解释掉了。**
> 
> **所以最靠前的硬要求是**：
> 
> **Windows 路径一律用 `Join-Path` 拼，绝不在命令字符串里内联反斜杠路径。**
> 
> **为什么它比前三条靠前**：前三条要求你**在危险操作前多确认**；
> **这一条要求你**根本不要构造出会被吃掉的字符串**。**确认是补救，不构造才是预防。**
> 
> **还有一条配套的**：**命令输出里出现「我预期的路径」时，多看一眼那行字。**
> **反斜杠没了、`\r` 把行拆开，这类损坏在输出里是看得见的——不看就会跳过唯一的现场。**
> 
3. **凡生成文本中含任何在中间语言里有语法含义的字符，一律不得整体塞进单条字符串字面量。**
   
   **字符类别（不是逐个列举——列举会漏掉高频项）**：
   `'` `"` 反引号（`` ` ``）`$` 反斜杠转义（`\n` `\r` `\t` …）
   **以及任何被该中间语言当作定界符或转义起点的符号。**
   
   **改法二选一**：
   - **数组逐行 + `join("\n")`**（writer-bcd 全程只用这一种）
   - **分多次用文件写入工具直接写**
   
   **实测数据（writer-bcd 本会话六次）**：
   ```
   1. 三反引号直接终止 JS 模板串      → Expected ',', got '<eof>'
   2. 双引号出现在双引号 JS 字符串里   → Expected ',', got 'How'
   3. 破折号落在字符串之外（+ 链断一处）→ UnexpectedChar { c: '—' }  ×2
   4. PowerShell 里嵌套双引号转义       → Expected ',', got 'string literal'
   5. JS 单双引号混写致 tbl 未定义       → ReferenceError: tbl is not defined
   6. 反引号包反引号（嵌套代码块）       → 同样直接截断
   ```
   **六次里只有一次是 `\r`，其余全是引号、反引号、破折号这类「在中间语言里有语法含义」的字符。**
   **所以按 `\n \r \t` 列举会漏掉真正的高频项。**
   
   **这与上面的反斜杠路径是同一根因的两侧**：路径侧写了「一律用 `Join-Path`」，字面量侧当时没写，于是又栽一次。
   **必须合并成一条——分成两条就会出现「修了路径侧、忘了字面量侧」。**
4. **给单条 tool 调用的文本量设一个上限，超过就分片。**
   **长到一定程度人也审不过来**：writer-bcd 有两次「写完才发现 partB 根本没生成、文件少了一截」，
   **靠「立刻回读并比字节数」兜住**——**若没回读，就会产出一份缺第五到第十节、而且长得完全正常的记录。**
4. **移动文件优先用 `Move-Item` 而不是「写一份 + 删源」**，
   前者是原子的，后者有一个「两份都在 / 两份都没了」的中间态。
4. **凡要报「已删除 / 已移动 / 已创建」之前，先 `Get-Item` 验一次目标**。

> **这与本轮反复在堵的洞是同一个**：
> **一个操作没报错，可能是「事情做成了」，也可能是「命令作用在了错误的路径上」。**

## 0. 角色隔离

- 你是独立审核员或修复员，不是流水线上其他角色。
- **任务书是唯一授权来源。** 任务书点名的文件可以读；任务书没有点名的 reviews/ 与 fixes/ 下的文件，一律禁读。
- **修复员必须读任务书点名的依据报告**，否则无从知道要修什么。若任务书要求你读某份报告而实际读不到，**停下来如实报告，不要靠猜、不要拿同类报告拼凑**。历史上出现过调度书点名一份报告、同时又禁止读整个目录的自相矛盾指令，直接导致一条中等缺陷漏修。
- 审核员：任务书点名了依据报告的（V 类复核），只许读那一份；R1 类首审通常不点名任何报告，那就一份都不许读。
- 严禁检索 docs/pipeline 下的历史文档以寻找答案（本规约与任务书除外）。
- **不采信上游任何自检结论。** 依据报告里的每一处引文、每一个数字、每一条缺陷描述，都必须回到题目原文逐字重新验证之后才可采信。依据报告写错是常事，发现时必须在报告里写出反证。

## 1. 字节级前置校验（必做，缺此项报告作废）

- 先用 [System.IO.File]::ReadAllBytes 读取被处理文件，计算 MD5 与字节数。
- 再用行读取工具复读全文比对，两次结果一致方可继续。
- 在报告开头以表格列出：文件路径、字节数、行数、MD5、是否一致。
- 若被修文件存在上游报告记录的基线 MD5，写出「基线对照」一行，指出当前 MD5 是否已变化；未变化说明修复未落盘，必须报告而非继续。

## 2b. 批次完整性闸门（PIPELINE L-63）

执行：`pwsh -Command "& docs/pipeline/check-integrity.ps1"`

它回答一个问题：**你手上这份审核报告的结论，对当前磁盘上的题目文件还成立吗？**
- `MATCH` —— 报告记录的题目 MD5 与当前一致，结论有效。
- `MISMATCH` —— 两者不同，说明文件在报告之后被改过，**那份结论对它已失效**，必须补一轮复核。
- `UNVERIFIED` —— 报告里没记 MD5（早期报告的通病），无法字节级判定；若同时提示「被改动」，按风险处理。

**归档与派复核之前必须先跑它。** 判据是 MD5，不是修改时间——mtime 会被无关的写入推动，MD5 不会。

**重要澄清（第 38 轮补）**：这个脚本**会读取 reviews/ 目录**——它必须读报告才能提取其中记录的 MD5。
RECHECK-G1 的核账员因此拒绝运行它，理由是「读取 reviews/ 属禁区」。**这个顾虑是对的，但裁定如下：**

- **子代理不必运行本脚本**。「禁读 reviews/」的纪律是为了防止子代理偷看别人的审核结论；
  而闸门脚本只提取 MD5 并与磁盘比对，不输出任何审核内容，**不构成信息泄漏**。
- **子代理若要运行它，可以运行**，并在报告里说明这是闸门而非人工阅读。
- **但更推荐的做法**：由调度方（我）运行闸门，把结果写进任务书，子代理只负责判断题目本身。
- 同理适用于 `verify-bank.ps1` 与 `wordcount-gate.ps1`。

**这条澄清本身也是一次 L-68 的复发**：我给子代理的禁令与我自己给它的工具互相矛盾，且没有说明谁适用。

## 2c. 答案序列的套利周期（L-85）

`verify-bank.ps1` 会检查答案序列是否存在**周期性**。判定范围是**所有不超过序列长度一半的周期**，
不只是常说的 2 到 6。

**为什么上限不能是 6**：B5 首版答案序列的前 8 位与后 8 位完全相同（周期 8），
**p=2 到 6 的检测全部查不出来**——而这种排列等于把一半题目白送给套规律的人。

**报告里必须写的四项**（A/B/C/D 要写，E 类无答案行写「不适用」）：
1. 周期检测：列出所测的 p 范围与结果。
2. **前半段与后半段是否互为重复**：偶数长度的序列必须单独判一次。
3. 最长连续相同：要求不大于 2。
4. 各字母作为正确答案的次数；**不得有全批一次都不作答案的字母**。

## 2b. 两条默认动作（第 114 轮补，writer-a 的统计触发）

**触发**：writer-a 在 A28、C6、C8 上**三次**栽在同一类方法坑（脚本的正则/提取出错、
但结论被当成发现报出）。**它自己的诊断比「缺一步」更准**：

> 「程序化扫描 + 原文直打」每次都兜住了，**可它是被出事之后才执行的**——
> **说明它的价值在于事后止损，不在于事前预防。**

**所以问题在触发机制，不在规则内容。** 以下两条写成**默认动作**，不是需要临场想起的纪律：

### 默认动作 A｜凡正则/脚本结果异常，先原文直打再下结论

**触发条件**：任何脚本、正则、解析器给出的结果与预期不符时。
**动作**：直接打印那一段原文，与脚本输出并排看。
**不得**在原文直打之前写出任何判定。

### 默认动作 B｜写完立刻回读并比字节数

**这条不属于「正则异常」那一类**，它是另一类：**我自己算的期望数字错。**
（writer-a 两次：估「56→39、−17」实为「53→37、−16」；估「−4」实为「−6」）

**所以回读比字节数不是可选的确认步骤，它是唯一能发现「我算错了」的检查。**

**两条的共同形式**：

> **一个步骤只有在不需要临场想起的时候才可靠。**
> **写下来的纪律如果依赖记忆，就是待办事项；写成默认动作才是控制。**

## 2a. 任务书里引用的实测数字必须标注来源（第 114 轮补）

**触发**：reviewer-4 在写 `CL-C8.md` 时发现，任务书让它转录「`R1-C8.md` 实测 0 个选项行、0 个 Q 标记」——
**而它实测是 3 行 / 85 行。那组数是 writer-a 在 C7 上的实测，调度方顺手套到了 C8。**

**根因**：调度方写任务书时引用别人的数字却没标出处。**本轮已五次**（C 类聚合率、A10-03/A13-04 配对、
A21/A16 数字、`F1-A32` 的 48 处、这次的 R1-C8）。

**规则**：
1. **任务书里引用的任何实测数字，必须标注来源（谁测的、什么时候）。**
2. **执行者若要把它写进正式记录，必须自己重测。**
3. **若重测结果与任务书不同，以自己实测为准，并在文件里写明更正**——**不得照抄**。

**reviewer-4 的更正表述比原表述更准**：
> 并非「完全没有」选项行，而是**没有逐题、可比对的选项原文**——全批 120 个选项，R1 侧只有 3 行，
> **覆盖率约 2.5%，远不足以构成第 3 列**。

**「0 行」和「3 行、覆盖率 2.5%」对结论没有区别，但后者是准确的描述。**

### 2a-1. 但只管「谁来测」不够，还要管「怎么算」（reviewer-4 补，第 114 轮）

**它的差异恰恰出在后者**：writer-a 在 C7 上测「0 个选项行」、reviewer-4 测 R1-C8 得「3 行」——
**但并没人知道 writer-a 当时用的是不是同一条判据。**

**若两者口径不同，「0」和「3」可能都对，只是量了不同的东西。**
（reviewer-4 的口径：`^\s*[-*]\s*[A-D]\.\s+\S` 或 `\|\s*[A-D]\.\s+\S`）

**所以规则补成**：

> **实测数字必须与判据一起记录：用什么正则／什么口径／在哪个范围内统计。**
> **两个数字只有判据相同才可比；判据不同时，「更正」这个动作本身是错的**——
> **应该先对齐判据，再比结果。**

**这条比「标注来源」更靠前**：
**来源只告诉你「谁量的」，判据才告诉你「量的到底是什么」。**
**只有来源没有判据，同样会出现两个都合法却互相矛盾的数字，然后照着「以自己实测为准」去覆盖**——
**那会把一个对齐问题当成纠错问题处理掉。**

**同类失效本日已发生多次**（reviewer-4 在 C6 用 `rows[$i] -eq "**Q3**"` 全文件扫描、匹配到别的题块；
读 R1 逐题表时把 5 列按 4 列解析、答案字母一列静默取空）——
**两次都是「判据写错了」，不是「数据取错了」。**

**该规则的效果（同一条正则产出的四批数字，reviewer-4 已写进 CL-C6～C9）**：

| 批次 | R1 含选项原文行数 | 全批选项数 | 覆盖率 |
|---|---|---|---|
| C6 | 0 | 120 | 0% |
| C7 | 0 | 120 | 0% |
| C8 | **3** | 120 | **2.5%** |
| C9 | 0 | 120 | 0% |

**四批结论一致：第 3 列在 R1 侧实质缺失 ⇒ 独立闭合结构性不可行。差异只影响描述精度、不影响判定。**

**为什么要 2a 这条**：
> **不只为纠错——它保证正式记录里出现的每个数字，都有一个人真正验过它。**

### 2a-2. 「当前／现在／目前」先问它指现实时间还是语境时间（第 191 轮补，reviewer-1）

> **同一个词在文档里可能指现实时间，也可能指语境时间。**
> **语境时间不会触发任何检查**——你不会去查「中考季是几月」，因为它不是日期，是常识。
> **这正是本条要防的事。**

**写「当前／现在／目前」时，一律先问：**

| 要写的 | 必须做的事 |
|---|---|
| **现实时间**（「现在」「目前全库有 X 个」） | **现场取一次系统时间**，不得凭印象 |
| **语境时间**（「考试季」「本轮」「考前」） | **必须显式标注语境**，如写「考试季（每年 4 月下旬）」，**不许让它冒充「现在」** |

**实例（第 191 轮真实事故）**：交付物里写「现在是 2026 年 6 月」。
**那不是记错月份，是把「中考季节」当成了当前时点**——它指的是考试季，不是当天。
**按错误类型看，它比单纯记错更隐蔽**：纯记错会被系统时间检查拦下；**语境时间冒充现实时间，不会被任何自动检查拦下。**

**交付日期单独一条**：**按工作实际发生的日期记，不按钟点归零重算。**
跨零点的连续工作是同一件工作，**改记为第二天等于制造一处新的不准确**。

### 2a-3. 匹配／替换的锚点必须来自实际读取的原文（第 191 轮补，reviewer-1）

**匹配与替换所依赖的锚点字符串，必须是你实际读到过的原文。**

**不许凭印象构造一个「大概在那儿」的字符串再拿它去匹配。**

**匹配失败时的正确反应：先打印原文确认。**

> **不许改用另一个工具重试。**
> **换工具不改变「我猜错了」这个事实。**
> 换一个工具再匹配一次，如果锚点仍然是猜的，结果仍然是错的——只是这次错得更慢、更难发现。

**实例（第 191 轮真实事故，同一晚两次）**：

- 要在 @COMMON.md@ 里 §2a-2 与 §2c-2 之间插入一节，锚点却写成两个井号的 @^## 2c-2.@；
  第一次用 Python 脚本报 @StopIteration@，**未打印原文**，改用 PowerShell；
  第二次用 @^## 2c-2\.@ 仍为空，**仍未打印原文**；第三次才 @ReadAllLines@ 把原文打出来——
  **实际是三个井号的 @### 2c-2.@，不是两个。**

**这与同晚「12 点 30 分钟写成 22 分钟」是同一个病：构造了一个没读过的字符串，然后当成事实用。**
**前两次之所以没发现，是因为默认反应是「工具不对」而不是「我猜错了」——**
**锚点匹配失败，第一嫌疑永远是锚点本身，不是工具。**

### 2c-2. 「复现脚本」不等于「看一眼脚本」——三个 bug 的共同形状是**复现得不够完整**

（reviewer-2 在独立复现 `check-integrity` 的 `Get-Rank` 时连出三个，采纳为规约）

**① 捕获组取错**
写 `(-(\d+))?` 却取 `m[1]`——**组 1 是 `'-2'`（带连字符）**，算出 `9000 + (-2) = 8998`，
于是「复现」得出「改动没用」的结论。**脚本取 `$matches[2]` 是对的，复现是错的。**

**② 打印了一句自己的数据不支持的话（本条最严重）**
console.log 里「⇒ CL-X-2(9002) 现在确实压过 CL-X(9001)」是**手打的字面量**，
而紧邻它上方的实测数是 **8998**。

> **算错会被下一行看出来；硬写的结论不会。**
> **「我打印了一句自己的数据不支持的话」比算错更坏**——它把一个错误结论和一段看起来严谨的输出绑在了一起。

**③ 只实现了主干，没实现回退分支**
只取 `strong` 路径，A8 的 `V-A8`/`R2-A8` 走 weak/first 回退，于是掉到 R1-A8 的过期强锚上，
**报出「A8 MISMATCH」——与实际 58 批全 MATCH 直接冲突**。

**规则**：
1. **要断言「脚本逻辑如此」，必须把回退分支也实现一遍。**
   **只实现主干 = 只验证了一半，然后拿这一半去否定别人。**
2. **结论文字不得手打。**要由实测数据生成，或紧邻地贴出那个数据——**让数字和结论在同一处产生**。
3. **复现结果与被复现者不一致时，先怀疑自己的复现**（本轮三次都是复现错，不是脚本错）。

## 2c-1. 「搜不到」有两种可能，别把第二种当成第一种（第 114 轮补，reviewer-4 实测）

**实测**：它在 R2-C6 里搜 `本批答案序列` 返回空，差点要报「末尾汇总行缺失」。

**实际原因**：C 类这批的汇总行标题是 **「本批汇总：… ／答案序列：」**，
而它照着 A 类的惯用词 **「本批答案序列：」** 检索。**检索串写死了一个批次的习惯，换批次就失效。**

**「看起来像文件缺这行，实际是我没搜对」——若当时报了，就会派一轮人去「补一行汇总行」，而那行一直都在。**

**规则**：
1. **凡要报「某项不存在」之前，先用第二种方式再找一次**：换检索串、换工具、或直接打印该位置的原文。
2. **在没核实之前不报缺失**——写「待验」，不写「不存在」。
3. **这是一个查询没返回结果的通用形态**，与以下同源：
   - 列表接口默认返回 50 条，被读成「板上最多 50 条」
   - 修复记录里只有词数四元组，被读成「有可比对基线」
   - `topic-guard build` 报「已是最新」，那次是改动前跑的
   - dispatch-guard 的退回路径把修前值当修后
   - 五道闸门全 PASS，但「题干说 the boy、正确项说 Her」无一道查得出
4. **一句话**：**一个查询没返回结果，可能是「东西不存在」，也可能是「你没搜对」。这两件事必须分开确认。**

## 2d. 文件可用性闸门（PIPELINE L-105）

执行：`pwsh -Command "& docs/pipeline/encoding-check.ps1"`

它检查每个题目文件是否**能被正常读取**：有无 BOM、有无 CRLF 混用、有无 U+FFFD 替换字符（编码已损坏）、末尾有无换行。

### 2d.1 写完自查清单（**第 4 项是第 194 轮补，前三项结构上查不出它**）

写完任何文本文件，逐项自查：

| # | 项目 | 口径 |
|---|---|---|
| 1 | CRLF 混用 | 计数 `[regex]::Matches($t,"`r`n")`，应为 **0** |
| 2 | 真 U+FFFD | 计数 `[regex]::Matches($t,[char]0xFFFD)`，应为 **0**。**不得数 `0xEF` 字节**——汉字 UTF-8 首字节全是 `0xEF` |
| 3 | 末尾换行 | 末字节应为 **0x0A** |
| 4 | **裸 CR**（**第 194 轮补**） | 计数 `[regex]::Matches($t,[char]13)`，**应为 0**；或直接用 `encoding-check.ps1` 判定 |

> **为什么第 4 项必须单列**：**前三项在结构上查不出裸 CR。** 第 1 项只匹配 `\r\n` **序列**，一个**孤立**的 `\r` 不构成 CRLF，计数恒为 0。
> 第 194 轮实测：reviewer-3 用 PowerShell 双引号 here-string 写入含 Markdown 反引号的文本，**静默污染 8 个文件**，
> **而写后自查三项（CRLF=0／FFFD=0／末尾 0x0A）全部通过**——是 `encoding-check.ps1` 抓出来的，
> 因为它的正则匹配**全部** `\r`，而非只匹配 CRLF。
> **闸门没问题，是临时自查项定得太窄。** 闸门能抓 ≠ 自查能抓；**自查清单必须独立于闸门覆盖。**

> **前三个闸门查的都是「内容对不对」，这一个查的是「学生端能不能打开」。**
> 题目写得再好，学生端解析出一个诡异字符或末行丢失，练不了。
> 起因：第 79 轮全库扫描查出 C3.md 末尾缺一个 LF——不影响任何判分，但会干扰按行切分的下游工具。

## 4. 写作纪律（出题与修复共用）

- **允许**（库内既有惯例，全部已归档批次都这么写）：
  - 文件开头的一级标题批次说明行，例如 `# D4 类 · 时间表类表格填空（10 份）`。
  - 其后的 `>` 引用块形式的出处说明行，例如 `> 来源：并行子任务产出｜共 10 份 / 30 空`。
  - 每份材料的题号标题行，例如 `## A7-01 调课`、`## C5-03 清晨五点的蔬菜摊`。这是 REVIEW-RUBRIC 1.6 规定的结构标记。
- **禁止**：任何**逐题逐份的**校验区块、角色方向自检表、逐项自检清单、考点对照表等面向作者的过程记录。判据是「这段文字是给学生做题用的，还是给流水线内部看的」。
- **这条禁令的由来**：L-45 曾要求出题员把「角色方向自检表」写进题目文件，结果把段数统计撑大、破坏了 1.9 的题数比门禁。**要禁的是这种自我审查痕迹，不是批次说明行。**
- **调度方对 1.6「混入说明性文字」的正式裁定（第 35 轮）**：
  - **允许**：批次开头的一级标题行、`>` 出处块、每份材料的 `##` 题号标题行。
    理由：库内 16 个已归档批次**全部**带这类行；若判它们违规，等于判整个题库违规。
    复核员若在旧版规约下把一级标题行判为严重，**该条一律作废**（V-E4-2 的严重缺陷 2 即属此例，已裁定降为不处理）。
  - **禁止，且判严重**：`## 角色方向自检表` 这类**逐组逐题的过程记录区块**。
    理由：它同时污染 1.9 的题数比门禁（E4 实测 ## 段数被撑成 11，使 20÷11=1.818≠2）。
  - 遇到介于两者之间的写法（例如带表格的批次说明），**先判断它是否计入 1.9 的段数统计**：计入则禁止，不计入则允许。
- **例外且必需**：每份材料的题号标题行（例如 `## A7-01 调课`、`## C2-03 校园义卖`）是 REVIEW-RUBRIC 1.6 规定的结构标记，必须保留，不得当作元数据块删除。
- HTML 注释块允许保留（词数口径本就排除注释块），但注释内不得出现答案或解题提示。
- 题目文件只许包含：题号标题行、材料正文、题干、选项、Answer 行、WordBank（仅 D 类需要）、注释块、文件末尾汇总行。
- 改文件前必须先读该文件。
- **改了材料里的数字或事实，必须回查所有引用它的选项。**（第 113 轮补，两处实例）
  R1-A11 的处方要改第 190 行为「We washed **both cars** at home」，而选项 D 的文本是
  「They washed **the car at home twice**」——照抄后**正确选项与材料互相矛盾**，把一条好题改成错题。
  R1-C6 的处方写「四个选项无需改动」，但选项 B 是「About **eighteen** thousand」，
  而短文改成 fourteen thousand 之后，四个选项（four/eighteen/eleven hundred/thirty-one thousand）
  **没有一个匹配 14,600**——从「认真核算的学生被惩罚」变成「任何学生都答不出来」，**更严重**。
  **两处都是审核员或调度方转述处方时的盲区：只盯着要改的那一句，没回查引用它的下游。**
  **规则**：凡改动材料中的数字、时刻、金额、件数、名称，必须列出所有引用该值的选项，
  逐条确认改动后它们仍然成立；不成立的一并改。**修复记录要写明回查了哪些选项。**
- **材料里的数字/时刻矛盾，先问「这句是不是被问的事实」。**（第 113 轮补）
  **实例（A23-11，调度方裁定）**：材料说 `By class number, one to forty`，学生 class 12，
  老师说 `Then you stand in the middle`。**1–40 的中点是 20/21，12 在前三分之一——字面上矛盾。**
  但题目问的是 `How should the students line up?`，答案 `By class number` **由第一话轮直接给出**；
  `Then you stand in the middle` 回答的是 Boy 的 what-if，**不在本题的解题路径上**。
  **所以「12 不是中点」这个矛盾不落在被问事实上，判轻微而非严重。**
  **本裁定不授权「有数字不符就一律轻微」**：若矛盾句**就是**被问事实、或答案要靠它才能定，
  **该判的仍是中等/严重。** 要看的是矛盾**有没有落在解题路径上**，不是矛盾**存不存在**。
  - **另两种读法并存时不能只取不利的那种定缺陷**；若存在同样通顺的一致读法，按 _COMMON §5.1 记中等以下。
  - **读法代价要如实记**（如「数字变得无关」是表述冗余，不是矛盾）——记下来比抹掉更有价值。
- **把任何报告当作「现行结论」之前，先确认同批次有没有后缀更大的版本。**（第 113 轮补）
  既定口径是「同一批次多份报告以文件名后缀最大的那份为准」。
  **实例**：writer-a 读 `R1-A30.md` 判某对跨批重复为假阳性，**却没有先确认 reviews/ 下是否已有 `R1-A30-2.md`**——
  他把一份已被取代的报告当成了现行依据。结论恰好对，但**依据建在作废文件上**。
  规则：**读某份报告下判断之前，先列一下同批次有哪些文件**（只列文件名与时间戳，不打开内容），
  **确认你读的是后缀最大的那份。**这个动作花几秒，能避免整节结论失去依据。
- **看到「前后不一致」先分辨是修复的成果还是修复的产物。**（第 113 轮补）
  **实例**：writer-bcd 看到 C7-03 的「被拒清单里没有红豆包，但末句说红豆包排队长到拐角」，
  判为「材料内部不自洽」并要求修。**核原文后是误报**——那次改动**正是为了消除矛盾**才做的：
  改之前红豆包既在被拒清单里又排队长到拐角，导致 Q5 三个选项都有逐字依据、无法排除任何一个。
  **规则：发现不一致时，把改动前后的两份都摆出来看，它到底在制造矛盾还是在消除矛盾。**
  本轮已三次因「不核原文就下判断」出错：调度方误引审核报告、reviewer-4 把 `it` 读成 `them`、
  writer-bcd 把修复成果读成修复产物。**核原文这一步不能省。**
- **零字节改动证明必须自带「自证失败」条件。**（第 114 轮补，reviewer-4 提出，不需改任何脚本）
  
  **实例（`F1-C6` 实测）**：它 L99-104 公布的那段 python 逐字照抄跑一遍是——
  ```python
  rev = cur
  # 依次执行上表 48 处 (新 -> 旧) 反向替换      <- 注释在这里，代码里没有任何 .replace()
  print(hashlib.md5(rev.encode('utf-8')).hexdigest())
  ```
  **实测输出 = 当前文件 MD5；它声称的 REVERTED MD5 与之不同。**
  `rev = cur` 之后没有替换动作，`rev` 恒等于 `cur`，**这段代码不可能算出它声称的那个值**。
  
  **根因：那段证明没有失败条件**——做没做替换，它都会打印一个 MD5 出来。
  
  **所以任何闭合证明必须至少含两条断言**：
  1. **`rev != cur`** —— 若替换未真正执行，此条为假，**证明立即失败**；
  2. **已应用替换处数 == 申报处数** —— 申报 48 而实际命中 0，此条为假。
  
  **两条都真，MD5 相等才构成闭合证据。**
  
  **这把「证明」从「打印一个数」变成「一个会拒绝的检查」**：
  - 零替换 → 直接失败，而不是安静地产出一个看起来像结论的数字；
  - **部分闭合**（申报 48、实际只替 40）→ 同样被抓住。
  
  **推广：凡是「跑得通就通过」的检查，都要问「它在什么都没做时是什么行为」。**
  一个永远通过的检查等于没有检查。
  
- **「零字节改动」的完备形式是「除申报项外全文与基线相同」，不是「申报项都闭合」。**（第 113 轮补）
  **实例（R2-A21 实测）**：F1-A21 申报了 12 条改动、§9 清单列了 14 行，反向替换全部闭合、MD5 逐位相等；
  **但 A21-03 另有一次选项重排 + Answer 由 C 改 D，既不在申报的 12 条里、也不在 §9 的 14 行清单里**——
  而 R1-A21 根本没把 A21-03 列为缺陷（判为「一致」），所以它**既不在授权范围内也不在缺陷清单内**。
  **后果：按 §9 清单逐条复审的审核员会漏掉它。** reviewer-1 独立复现时正是先撞上「MD5 对不上基线」，
  穷举四个选项文本的全部排列才定位到这一组。
  **根因**：清单驱动的复审**天然只会去核清单上的条目**，清单漏一条，那个洞就闭合不上。
  **规则**：
  1. 修复记录的「改动清单」必须是**全部改动的穷举**，不是「我打算做的」。
  2. 复审时除了逐条闭合清单项，**还要能说清「未申报的改动为零」**——
     典型做法是报告除基线与当前的文件外，再对当前文件跑一次「与基线的有向差异」并逐处归因。
  3. **重排选项行序要逐项申报**，哪怕该题不在缺陷清单内——
     因为重排是最容易被漏报、且一旦漏报就完全不可见的一类改动。
- **处方不完整时，「照做」不等于「修复」。**
  审核报告给出的改法必须覆盖该缺陷描述里的**每一个分句**；若只覆盖一部分，
  报告必须明写「本处方只处理第 X 部分」，否则修复方会把「已照做」当成「已修完」，
  而记录里的「已修复」会让后面每一轮都不再回看这里（L-94）。
- **采用了「有代价」的做法，必须把代价一起交上来。**
  凡你选的方案在解决 A 的同时弱化了 B（哪怕 B 只是变轻微），必须在修复记录里写明：
  代价是什么、是否可逆、以及在什么条件下应该换一个做法。（L-97）
- **修复员的授权范围包含被修的题目文件本身。**任务书要求你「只许写一个输出文件」指的是**新写**的文件（修复记录）；
  **修改任务书点名的那个题目文件，是修复员的本职工作，不受此限。**
  （第 43 轮教训：我同时写下「只许写 fixes/F3-E1.md 一个输出文件」与「只改这 5 条考点行」，
  修复员据此判定两条指令冲突，只能按后者理解并把疑虑写进报告。**任务书不要把「新建」与「修改」混在一句里说。**）
- 不得创建规范之外的目录或文件。
- **修复记录文件名由「被修复的那份审核报告的轮次」机械推导，不得自行发挥：**
  `R1-X.md` 报出的问题 -> `fixes/F1-X.md`；`R2-X.md` 报出的问题 -> `fixes/F2-X.md`。
  `F3-X.md`、`F4-X.md` 只在确实发生了第三、第四轮修复时才出现，**不要因为批次是第三轮就写成 F3**。
  （本条此前写错过一次：曾举例「R2-C3 对应 F3-C3」，正确应为 F2-C3。V-C4 的复核员据此提出过口径疑问。）
- 复核轮的编号同理：`V-X.md` 是第一次复核，`V-X-2.md` 是对同一批次的第二次复核，`V-X-3.md` 是第三次。
  同一批次存在多份 V 报告时，**以文件名后缀最大的那份为准**，更早的结论对它已失效。
  **落点必须取「下一个可用后缀」，不是一律 `-2`。**（第 113 轮补）
  **实例**：C7 已有 `V-C7.md` 与 `V-C7-2.md`，C8 已有 `V-C8.md` 与 `V-C8-2.md`。
  此时再按 `-2` 落盘**会直接覆盖已存在的 V-C7-2.md / V-C8-2.md**——正是「不得覆盖」禁止的事。
  正确落点是 **C7 → `V-C7-3.md`、C8 → `V-C8-3.md`**。
  **落盘前必须先列该批次已有的 V 报告文件名**（只列元数据、不打开内容），取最大后缀 +1。
  **发现者**：reviewer-3（任务书写「已有则写 -2」，它照做会毁掉两份已存在的报告）。

## 5. 缺陷分级

- 严重：答案错、答案不唯一、材料自相矛盾、题目无法作答。必须修。
- 中等：依据虽在但需跨句绕路才成立、题干泄露答案、推理链断裂、考点重复、配比失衡。应当修。
- 轻微：表述生硬、套话重复、词数余量偏小。记录即可，可择机修。

### 5.1 「材料算错了」到底算严重还是中等（第 112 轮裁定）

R1-B6 提出一个真实的定级困境：材料里 1 米 = 100 厘米、每片 30 厘米，
却写成「one metre gives me five pieces」（正确是 3 片）。**这是材料自相矛盾**，
而 _COMMON §5 把「材料自相矛盾」列为严重；但该题答案仍正确且唯一，中等也说得通。

**裁定：判据是「按材料算」与「按正确算」两条路径会不会落到不同答案。**

| 情形 | 定级 | 理由 |
|---|---|---|
| 两条路径**落到不同答案** | **严重** | 认真算的学生会被判错。**正确的推理过程受到惩罚**，这是判分有效性问题，不是表述问题。 |
| 两条路径**落到同一答案** | **中等** | 没有任何学生因此吃亏——跟材料算的对，算得对的也对。算式仍然必须改，但它不是判分完整性问题。 |

**理由**：严重档的判定标准是「缺陷是否破坏判分有效性」，不是「缺陷是否存在」。
把「材料里有错算」一律判严重，会让审核员对无害的错算也开严重单子，
而严重档一旦通货膨胀，真正破坏判分的缺陷就淹没了。
**R1-B6 三条中等的定级予以确认**（三条都是两条路径同答案）。
- 报告必须给出「严重 X 条｜中等 Y 条｜轻微 Z 条」的明确计数，不得只写叙述。

## 6. 报告格式

- 第一节必须是「结论」：是否通过、能否放行、缺陷计数、是否可进入下一环节。
- 逐题逐选项判定，不得抽样。必须给出「已复核题号清单」表格，列出每个题号的严重/中等/轻微列。
- 最后必须有「最终判定」一句话，直接写通过或不通过。
- 不得因为「不适用」就把门禁写成 PASS。门禁不适用时写「不适用」并说明理由。

## 6.5 归档记录（`reviews/CL-<别名>.md`）的结构 —— **第 191 轮建，此前无任何规约**

> **本节是新建的规约条目。** 建之前的实况：`CL-*.md` 的六节结构**没有任何文件定义过**——
> `_COMMON.md` 无归档记录小节，`ARCHIVE.md` 是编年流水账、不是结构规约，
> `BATCH-OWNERSHIP.md`、`catalog.md` 亦无。**它一直是口头约定**，
> 所以「写作者漏写」与「模板没要求」分不开。**先建规约，再谈补存量。**
> 证据：`docs/research/CL-BOUNDARY-AUDIT.md`（第 191 轮普查，46 份 CL 逐份回读）。

### 6.5.1 六节骨架（缺任一节即不合格）

> **为什么列成条目，而不是写「参照 `CL-A32.md`」**（第 192 轮补）：
> 本库此前的 CL 骨架**从无规约**，`CL-A32`／`CL-D5`／`CL-A7` 三份结构一致，
> **不是它们遵守了规约，而是三个人按同一种习惯写了出来**——**习惯不是规约**，会随人变。
> 更实际的风险：**只写「参照样本」产出的是抄件；抄件之间的差异会被下游误当成内容差异。**
> 写「必须包含以下六节」，产出的是**各自独立、但结构可比的记录**——那才可核。

1. 三句固定首行 + 明确断言（**达成闭合 / 未能闭合**）
2. **基线表**：文件、MD5、字节、行数、末字节；**现场重算**，并注明行数口径
3. **报告链**：逐条标来源报告 + **行号** + 是否锚定当前 MD5
4. **未闭合项**：逐条转录，每条注明出处行号
5. **四条边界**（见 6.5.3）
6. **纪律段**：声明未改题面文件、未改既有报告

### 6.5.2 【必填】库级边界小节 —— **自第 191 轮起为必填**

**任何一份 CL 都必须写下面两条边界；它们不是待办，是外部条件。**

| 边界 | 适用范围 | 内容 | 解除条件 |
|---|---|---|---|
| **① 课标五级词表不可得** | **全部批次必填** | 词表缺失，**1.3 超纲词这一项无法判定，不是不合格** | 取得课标五级词表或省级发布词表 |
| **② 中考口语考纲不可得** | **仅 E 类必填** | 本库无中考口语考纲，**无法证明内容对齐中考**；A/B/C/D 是听力，不受此条约束 | 取得《江苏省初中英语听力口语自动化考试纲要（试行）》或苏州市教育局基教处书面口径 |

**两条都必须写明「不计入未闭合项」。** 理由：**缺陷清单的语义是「这活还能干」**，而这两条永远干不了——
把它们列成缺陷，会让读者以为「补上词表／考纲就能复审通过」，那是**不可能的**。
**分类错了比漏了更坏。**

写法样本：`reviews/CL-E3.md` §4.5/§4.6（两条最完整）、`reviews/CL-C5.md` 边界①行。

### 6.5.3 四条边界（每份 CL 必写）

- 6.5.3.1 不断言「内容无缺陷」——**闭合是独立性质，缺陷层面通过不等于已核准**
- 6.5.3.2 **闸门全绿是必要条件，不是充分条件**
- 6.5.3.3 **MATCH 只担保同一性（当前磁盘字节 = 报告所记字节），不担保正确性，也不担保历史改动已全部归因**
- 6.5.3.4 参与判定的每个数字**标注来源与口径**；**不得出现无行号的「转录自 Rn-X」**

### 6.5.4 存量不追溯

本节**自第 191 轮起对新写 CL 生效**。此前已存在的 CL **不要求补写 6.5.2**，
但**读旧 CL 的人必须知道这两个维度它判不了**——覆盖率索引见
`docs/pipeline/COVERAGE-BOUNDARIES.md` 全库级别小节（边界① 12/59、边界② 2/4）。

## 6.6 审核方法：凡「有参考作答 + 有评分要点」的题型，**必须三方对读**（第 194 轮补）

> **这是一条检查方法的盲区，不是内容缺陷。** 来源：V-E8 实测。
> 它对口语「话题简述」整型成立，**今后每一批都会踩**。

### 6.6.1 原有的查法（**只覆盖一半**）

要点点名的每个词／结构，**必须真实存在于该题的参考作答里**。这一条只覆盖 **要点 ↔ 作答**。

### 6.6.2 缺失的查法：**必须同时读「话题题目 → 评分要点 → 参考作答」三方**

只做 6.6.1 会漏掉「**要点改问了别的问题**」——**要点里的每个字串都对，但对应的是作答的某个角度，不是题目的那个问题。**

**V-E8 实测实例**：

- E8-07 题目问「**你最喜欢的节日**」（个人偏好），
- 参考作答只说「**中国最重要的节日**」（**国家客观事实，非个人偏好**）——**题目问的缺口，作答本身就没填**；
- 而评分要点被改成「**节日重要性**」——于是**要点能拿满「信息完整性」分，而这个缺口对评分者完全隐形**。
- 全批 **12 题里 5 题的「题目第二问」在要点里被换掉或没有对应项。**

### 6.6.3 判定口径：**三者是三个断言，必须分别验**

> **要点与作答一致，不推出要点与题目一致。**

| 断言 | 查法 |
|---|---|
| 要点 ↔ 作答 | 要点点的词／结构在作答中真实存在 |
| **要点 ↔ 题目** | **要点所问的角度，与题目实际问的是同一件事**（含「题目的第几问在要点里有没有对应项」） |
| 作答 ↔ 题目 | **作答是否真的回答了题目问的那件事**（回答偏题、或只答了其中一个问，都是缺口） |

**三条任缺其一，都会让「题目没被回答」这件事对评分者隐形。**

### 6.6.4 适用范围

**对所有「有参考作答 + 有评分要点」的题型成立，不限于话题简述。** 凡出现「评分要点」这一层的题型，一律按 6.6.2 三方对读。

> **与 §6.5 的分工**：§6.5 约束的是**归档记录（CL）该有哪些小节**；本条约束的是**审核时该怎么查**。**本条是审核方法，不是记录结构，故不并入 §6.5。**

## 7. 纪律（历史教训）

- 历史上出现 20 次「报告原文无法被逐字复制」的事故，其中 4 次源于调度方本人写错。凡是你在别的报告里读到的编号、结论、引文，都必须回到原文重新验证后再引用。
- 发现上游报告或调度指令与原文不符时，必须在报告里明确写出「该声明不成立」并给出反证，不得沉默执行。
- 不得为了让报告好看而放宽门禁。判分有效性优先于一切美观与整齐。
