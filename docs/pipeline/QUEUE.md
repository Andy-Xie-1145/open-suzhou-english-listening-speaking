## 六、纪律速查（每一条背后都有一次真实事故）

- 归档前必须 `check-integrity.ps1` 判 **MATCH**（L-63）。
- 例外归档三条缺一不可：报告**事先**授权 + 调度方**亲自复现**「除此之外零改动」 + 全程落盘（L-79）。
- 修复记录名由报告名机械推导，轮次按**实际发生次数**（L-24、L-69）。
- 任务书输出路径**逐字手写**（L-69）。
- **清单总数与检查结果吻合时仍要逐条核**——错得对称时总数也是对的（L-88）。
- **涉及定级的条款必须标注 REVIEW-RUBRIC 条目号；自己加的「更严要求」以规约为准**（L-89、L-104）。
- **凡写「实测值」的数字必须能指到一次测量**，多处副本一起更新（L-90）。
- 引用原文用**逐字原句**，不用句子序号（L-65）。
- 每条指令自问：**在它被允许的范围内可执行吗**（L-68）；区分「新建」与「修改」的授权（L-68 第四种形态）。
- **闸门可以读 reviews/，人工阅读不行**（L-76）。
- 「不适用」不得报成 PASS（L-62）；门禁 FAIL 先确认是不是并发时间差（L-66）。
- 派规格时能从模板读出的就让子代理去读模板，**不要转述**（L-70）。
- 禁令措辞必须排除它自己要保护的东西（L-67）。
- **上游给的修复方案本身可能是坏的、也可能是不完整的**（L-78、L-94）；**处方里的数字也要自己算**（L-96）。
- **能穷举就不要抽样**；方向一致但数字对不上时数字也必须重算（L-83、L-87）。
- **概率的单调性是免费的证伪工具**（L-92）。历史缺陷记录会静默失效（L-81）。
- **规范自相矛盾比规范缺失更危险**（L-84）。
- **门禁里每个「范围/阈值」都要问：它是推导出来的还是惯例**（L-85、L-95、L-104）。
- **一条缺陷潜伏很久，先问「有没有为它写过检查」**（L-86）。
- **被指定为「唯一依据」的东西，检查成本会上升**（L-91）。
- **采用了「有代价」的做法，必须把代价一起交上来**（L-97）。
- **「需要读两句话」不等于「需要推断」**（L-98）。
- **把「目标是否达成」变成一个可重复运行的检查**（L-99）；**题库必须能被看见**（L-100）。
- **闸门报的每一条，先假设也许错的是我**（L-101、L-102）。
- **答案键的机械规律是最隐蔽的漏洞**（L-103）。
